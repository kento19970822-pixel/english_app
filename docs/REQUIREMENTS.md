## 1. 全体概要・システム要件

### 1.1 全体概要

本アプリは、ゲームの爽快感（2レーン落下式アクション）と科学的な記憶定着アルゴリズム（エビングハウスの忘却曲線モデル）を融合させた英単語学習アプリです。

直感的なクイズゲームによるアウトプットと、単語帳での検索・フィルター・ソート（A-Z / Chap / Category）・スワイプ・長押し・手動チェック操作によるインプット、そして毎日の連続プレイ（ストリーク）をトリガーとしたコレクター要素（プロシージャル生成ドット絵スタンプ図鑑・成長するドット絵キャラクター・相棒キャラクター）により、学習の習慣化と高効率な記憶定着を実現します。

### 1.2 システム要件

- **対応プラットフォーム**: Windows (Desktop), Web, iOS, Android（Flutterクロスプラットフォーム）
- **開発言語 / フレームワーク**: Dart / Flutter
- **2Dゲーム・ドットアニメーションフレームワーク**: Flame
- **ローカルデータベース**: Drift (SQLite)
- **音声・効果音機能**: FlutterTts (TTS再生) / AudioPlayers (SE再生)
- **デザインコンセプト**: パステルカラー × レトロドット絵世界観
  - メイン背景: `#FBF7EE`
  - カード: `#FFFDF9`
  - プライマリアクセント: `#5F9E98`
  - セカンダリアクセント: `#ECA882`
  - ボトムナビ: `#D4B86A`

### 1.3 Flutter / Flame の役割分担

本アプリでは、**通常のアプリUIをFlutter、ドット絵キャラクターのアニメーション・移動・エフェクト等をFlame**で実装する。

```text
Flutter
│
├── 通常のUI
│   ├── ボタン
│   ├── 設定
│   ├── メニュー
│   └── 画面遷移
│
└── Flame
    │
    ├── キャラクター
    ├── アニメーション
    ├── 移動
    ├── エフェクト
    └── 状態管理
```

#### Flutter側で担当するもの

- ホーム画面、単語帳、図鑑、カレンダー等の通常画面UI
- ボタン、検索バー、フィルター、ソート、設定、メニュー
- 画面遷移
- DBアクセス
- 学習ロジック・定着度計算
- TTS / SE のサービス呼び出し
- Flameへ渡すキャラクター状態・表示条件の管理

#### Flame側で担当するもの

- ドット絵キャラクターの描画
- キャラクターの歩行・待機・笑い・睡眠等のアニメーション
- キャラクターの画面内移動
- 音符・キラキラ等のドットエフェクト
- 状態に応じたアニメーション切替
- キャラクターとエフェクトのフレーム更新
- Flame内で必要となるキャラクター状態管理

#### FlutterとFlameの境界

Flutter側が「**何の状態を表示するか**」を決定し、Flame側が「**その状態をどのようにドットアニメーションとして見せるか**」を担当する。

例:

```text
Flutter
  ↓
「相棒キャラは現在 happy 状態」
  ↓
Flame
  ↓
笑顔アニメーションを再生
  ↓
条件を満たす
  ↓
音符エフェクトを表示
```

### 2.2 詳細アルゴリズム・ルール仕様

#### 🎮 ① 2レーン落下ゲームのゲーム性・動作メカニズム

1. **画面レイアウトと左右独立レーン**
   - 画面上部に統合スコア・コンボバーを配置。
   - 下部は左右に完全分割された2つのレーン（左: ブルー基調、右: インディゴ基調）で構成。
   - 各レーンは「上部: 落下エリア（単語カード＋3分割判定線＋フィードバック）」と「下部: 4択選択肢ボタンエリア」に分離する。

2. **左右2レーンの時差スタート・並行制御**
   - ゲーム開始時: 右レーンが第1問目として即時スタート。
   - 右レーン開始から **2秒後** に左レーンが第2問目として追随スタート。
   - 右レーンで即答した場合は2秒を待たずに左レーンを即時発進させる。

3. **単語落下・選択肢生成・音声（TTS）**
   - 単語カードが指定秒数（デフォルト8秒）かけて垂直落下する。
   - 出題単語が画面にセットされた瞬間、自動で英語音声を1回再生する。
   - 4択は正解日本語訳1個＋同レベル内の他単語から抽出した誤答日本語訳3個とする。

4. **解答判定・コンボ・SE・フィードバック**
   - 正解時: `correct.mp3`、コンボアップ、位置に応じた加点。
   - 誤答/タイムオーバー時: `wrong.mp3`、コンボリセット、-50pt、制限フラグ付与、未クリア単語は問題キュー末尾へ再ロード。

5. **画面離脱時の状態保護**
   - アクションバーの戻るボタン、物理バックボタン、ジェスチャーナビゲーションによる離脱を `PopScope` で検知する。
   - `onGameStateChanged(false)` 等を経由して、親画面のボトムナビゲーションバーを確実に復元する。

---

#### 🧠 ② 定着度ポイント（retention_point）およびフラグ制御ルール

1. **基本設計**
   - ポイント範囲: `0`〜`100`pt（初期値: `0`pt）。
   - `is_memorized`: `retention_point >= 80` に達した瞬間に `true`。
   - 忘却減算等により80pt未満になっても `is_memorized` は自動では外さない。F-09の一括メンテで解除する。
   - **1ゲーム1変動原則**: 1セッション中に同一単語が複数回出現しても、ポイント変動・フラグ更新は初回回答時の1回のみ。

2. **クイズ解答時の加算・減算ライン**

| 判定 | ゾーン | 変動 |
| --- | --- | ---: |
| Fast | 上部1/3 | +50pt |
| Normal | 中部2/3 | +30pt |
| Slow | 下部3/3 | +10pt |
| Miss | 誤答/タイムオーバー | -50pt |

- Fast: 「💥 Great!!」＋高音SE
- Normal: 「👍 Good!」＋通常SE
- Slow: 「👌 OK」
- Miss: 「❌ Miss」＋失敗SE

3. **制限フラグ（`is_restricted` / 当日上限70pt制限）**
   - 付与条件: クイズで誤答・タイムオーバー、または単語帳で左スワイプ。
   - 効果: 同日中は70ptが上限となり、その日中は80pt（暗記済み）に到達できない。
   - 解除条件: 日付が変わり、アプリ起動時の日跨ぎ同期処理が実行されると自動解除される。

4. **単語帳での直接操作**
   - 右スワイプ: `retention_point = 80`、`is_memorized = true`。
   - 左スワイプ: `retention_point = 0`、`is_memorized = false`、`is_restricted = true`。
   - 単語帳とお気に入り状態・定着度ポイントはDBを介して即時同期する。

5. **暗記フラグ更新（F-09）**
   - `retention_point < 80` に下がっている「暗記済み」単語の `is_memorized` を一括で `false` に更新する。

#### 📉 ③ 忘却曲線ロジックと1日1回日跨ぎ一括処理

アプリ起動時（または日付変更後の初回起動時）、前回の実行日 `last_daily_sync_date` と今日の日付 `YYYY-MM-DD` を比較し、日付が変わっている場合のみ1日1回の一括更新処理を実行する。

1. **一括処理内容**
   - 忘却減算: 各単語の最終解答日時からの経過日数と累計正答回数をもとに `retention_point` のみ減算する。
   - 制限解除: `is_restricted` をすべて解除する。
   - パフォーマンス維持のため1日1回のみ実行する。
   - `is_memorized` は自動変更しない。

2. **計算式**

$$
\text{次回定着度}
=
\text{現在の定着度}
\times
\left(
1-\frac{\text{経過日数}}
{\text{経過日数}+2+(\text{正解回数}\times2)}
\right)
$$

#### 🎮 ④ クイズモード別詳細ルール

1. **学習モード**
   - 通しチャプター単位で指定して実行（初期値: Ch.1）。
   - 出題対象:
     - `is_memorized == false`
     - または `retention_point < 70pt`
   - `is_restricted == true` の単語も復習対象に含める。
   - チャプター内の全単語（最大100語、端数チャプターは実際の単語数）に対する暗記率を算出。
   - セッション/周回終了時点で暗記率 **90%以上** を達成した場合、「Ch.X MASTER! 🎉」を表示し、次の通しチャプターを自動解放・移行する。

2. **チャレンジモード**
   - **制限時間1分間 / 100問連続出題**。
   - 全単語（暗記済みを含む）からランダム出題する。
   - 暗記済み単語（`is_memorized == true`）をFast（+50pt）で即答した場合、`is_restricted`を無視して、ポイントを一発で最大値の `100pt` へ完全回復する。
   - 上記の完全回復は、同一セッション内の1ゲーム1変動原則に従う。

#### 📖 ⑤ 単語の階層構造（レベル・チャプター）と粘着ヘッダー仕様

1. **レベル（Level 1〜6）と通しチャプター**
   - 全単語は難易度（CEFR等）に応じてレベル1〜6に分類する。
   - 各レベル内の単語は原則100単語ごとにチャプター化する。
   - チャプター番号はレベルを跨いでもリセットせず、アプリ全体で1からの完全通し連番とする。
   - レベル末尾の余り単語は100語未満でも1チャプターとして構成する。

2. **粘着ヘッダー**
   - チャプターごとの境界バーに総単語数および暗記率を表示する。
   - 例: `Ch. 1 (暗記率: 85% - 85/100語)`。
   - 端数チャプター例: `Ch. 11 (暗記率: 100% - 42/42語)`。

3. **単語カード**
   - 左端: 暗記済みインジケータ
   - 中央: 英単語・発音記号・和訳（長押し一時表示）
   - 右端: 発音ボタン・レベル/チャプターバッジ・お気に入り☆ボタン
   - 制限フラグ保持単語には「⚠️ 本日上限70pt」を表示する。

---

#### 📖 ⑥ 単語帳の検索・フィルター・3種ソート仕様（F-06）

1. **画面構成**
   - `検索バー (Search Bar)`: 英単語または和訳の部分一致検索
   - `ソート切替バー (Sort Toggle)`: `Chap`（章別） / `A-Z`（アルファベット別） / `Category`（テーマ別）
   - `横スクロールフィルターバー (Horizontal Scroll Filter Bar)`:
     - `[未暗記]`: 未暗記単語のみ絞り込み（タップでON/OFFトグル）
     - `[お気に入り ★]`: お気に入り単語のみ絞り込み（タップでON/OFFトグル、未暗記と同時選択可）
     - `[CEFR: 全て ▾]`: CEFRレベル（A1〜C2）選択ドロップダウン
     - `[Chap: 全て ▾]`: 通しチャプター選択ドロップダウン
     - `[A-Z: 全て ▾]`: 頭文字アルファベット選択ドロップダウン
     - `[Category: 全て ▾]`: 単語カテゴリ選択ドロップダウン（実データから動的抽出）
     - `[和訳スイッチ]`: 和訳表示の常時ON/OFF切替
     - ※「すべて」ボタンは廃止。未選択時は自動的に全件が対象となる。
     - ※スマホ等の画面幅が狭い端末でも横スライド（スクロール）で見切れた要素を操作可能。
   - `単語一覧リスト`: 各セクションごとの単語カードリスト

2. **可変ヘッダー**
   - 下方向スクロール（コンテンツ上昇）で検索・ソート・フィルターエリアが画面外へスライドアウトする。
   - 上方向へスクロールするとスクロール速度と同じ速度でなめらかに再表示する（`SliverAppBar(floating: true)`）。

3. **分類モード**
   - **Chap**: 通しチャプターごとにセクション化。各チャプターの暗記率プログレスバー（%）を表示。
   - **A-Z**: 単語のアルファベット頭文字ごとにセクション化。
   - **Category**: 単語テーマ（くだもの・職業・動詞等）ごとにセクション化。進捗バーを表示。

4. **粘着セクションヘッダー**
   - スクロール時、現在表示中のセクション見出し（例: `Category: Fruits & Vegetables` / `Chapter 1` / `A`）を画面最上部に固定表示する。

#### 🎨 ⑦ プロシージャル生成ドット絵スタンプ・抽選・手動拡張ロジック（F-11 / F-12）

1. **ドット絵スタンプの自動生成**
   - アセット画像ファイルに依存せず、Dartコード内でカラーパレット、顔・装飾パーツ、フレーム、背景エフェクトのシード値を組み合わせ、レトロ感のあるドット絵スタンプを生成・描画する。
   - スタンプ自体はFlameキャラクターとは別系統のコレクター要素として扱う。

2. **1日1回押印と安全な獲得判定**
   - その日の1回目のゲームクリア時に自動判定・演出表示する。
   - 累積学習日数、ストリーク、総暗記数、暗記チャプター数等を解放条件に利用する。
   - 未達成条件のスタンプが抽選された場合はフォールバックとして条件なし/達成済みスタンプを割り当て、毎日必ずスタンプを獲得できる。

3. **レア度と出現率**
   - Normal: 70%
   - Rare: 22%
   - Super Rare: 8%

4. **初期生成（Phase 1）**
   - 初回起動時に20個生成。
   - Normal: 14
   - Rare: 4
   - Super Rare: 2

5. **図鑑拡張**
   - 現在解放中の図鑑の獲得率80%以上で「✨ 図鑑拡張（Phase UP）」ボタンを表示する。
   - タップ時に演出を行い、新たに20個を生成する。
   - Phase 2以降は条件を段階的に難化させる。
   - 物理的上限を超える条件はキャップし、到達不可能な条件を生成しない。

#### 🎨 ⑧ 章ドットキャラ＆定着率連動（F-13）

1. **表示条件**
   - 単語帳を **Chap表示** にした場合のみ、チャプター見出しと第1単語の間にドット絵キャラクターを表示する。
   - キャラクターの右横に `Learned %` と進捗バー（例: `8/50`）を表示する。
   - A-Z / Category 表示では、現状キャラクターを表示しない。

2. **定着率算出式**

$$
\text{定着率(\%)}
=
\left(
\frac{\text{該当チャプター内の定着度80pt以上の単語数}}
{\text{該当チャプター内の総単語数}}
\right)
\times100
$$

3. **キャラクター状態**

| 状態 | 条件 |
| --- | --- |
| 👤 シルエット（未解放） | 過去に一度も定着率20%以上に到達していない |
| 🥀 元気がない | 20%以上達成経験あり、現在0〜49% |
| 😊 元気 | 現在50〜79% |
| 🌟 進化 | 現在80〜100% |

4. **Flame実装**
   - キャラクター本体はFlameで描画する。
   - 状態に応じてFlame側のアニメーション・表示パターンを切り替える。
   - Flutter側の定着率ロジックとFlame側の描画ロジックを分離する。

#### 🎨 ⑨ 2系統図鑑・相棒システム・ホーム演出（F-12 / F-14）

1. **スタンプ図鑑**
   - 1日1回の初回ゲーム完了時にスタンプを獲得する。
   - Phase UP により次の20個を追加生成する。

2. **キャラクター図鑑**
   - チャプター進捗で解放されたドットキャラクターを一覧表示する。
   - キャラクターの詳細情報を確認できる。
   - 好きなキャラクター1体を「相棒」に設定できる。
   - 図鑑拡張と新規キャラクター解放演出の完全連動は将来拡張事項とする。

3. **ホーム相棒キャラクター**
   - ホーム画面に相棒キャラクターを常駐させる。
   - Flameで自律アニメーションを実行する。
   - 基本状態:
     - 歩く
     - 笑う
     - 放置時に眠る
   - ゲームクリア後にホームへ戻った際はハミング音を発声する。
   - お気に入りスタンプが設定されている場合、相棒キャラクターの左胸に小サイズのスタンプバッジを描画する。

#### 🧭 ⑩ 下部ナビゲーション・ゲーム選択画面仕様（F-15）

##### 1. 下部画面切り替えタブ

アプリの通常画面では、画面下部に以下の3つのタブを表示する。

| タブ | 表示名 | 役割 |
| --- | --- | --- |
| 1 | **ゲーム** | ゲームモード選択・レベル選択・チャプター選択・ゲーム開始 |
| 2 | **単語一覧** | 単語帳の表示・検索・フィルター・ソート |
| 3 | **記録（仮称）** | カレンダー・スタンプ図鑑・キャラクター図鑑への入口 |

- 通常時は下部ナビゲーションを表示する。
- ゲームプレイ中は既存仕様どおり下部ナビゲーションを完全に非表示とする。
- ゲーム終了または離脱時は、呼び出し元画面のナビゲーション状態を確実に復元する。
- 「記録」は仮称とし、正式名称は今後決定する。

##### 2. 「記録（仮称）」タブ

「記録（仮称）」タブを選択すると、記録関連機能への選択肢を表示する。

```text
記録（仮称）
├── カレンダー
├── スタンプ図鑑
└── キャラクター図鑑
```

各機能の既存仕様は維持する。

##### 3. 「単語一覧」タブ

「単語一覧」タブを選択すると単語帳画面を表示する。検索、フィルター、A-Z / Chap / Categoryソート、可変ヘッダー、粘着セクションヘッダー、長押し、TTS、スワイプ等の既存単語帳仕様を適用する。

##### 4. 「ゲーム」タブ

「ゲーム」タブを選択すると、ゲーム開始前のゲームモード選択画面を表示する。

```text
ゲーム
├── ゲームモード選択
│   ├── 学習モード
│   └── チャレンジモード
├── レベル選択
├── チャプター選択
└── 開始ボタン
```

添付イメージには3パターンのゲーム選択画面デザイン案が示されている。現時点では採用パターンを決定せず、3案を候補として保持する。機能要件はデザイン案によらず共通とする。

##### 5. ゲームモード選択

| モード | 内容 | チャプター解放 |
| --- | --- | --- |
| **学習モード** | チャプター単位で集中学習 | **発生する** |
| **チャレンジモード** | 全単語からランダム出題 | **発生しない** |

- チャプター解放判定は学習モードのクリア時のみ実行する。
- チャレンジモードの結果によって次チャプターを解放してはならない。

##### 6. レベル選択

既存のレベル1〜6 / CEFR等による難易度管理を使用する。画面上では以下の難易度グループとして表示できる。

- 初級（A1 / A2）
- 中級（B1 / B2）
- 上級（C1 / C2）

具体的なビジュアルは添付3案の最終採用デザイン決定時に確定する。

##### 7. チャプター初期解放

各レベル / 各チャプター系列では、**最初のチャプターのみを初期状態で選択可能**とする。

##### 8. 学習モードによるチャプター解放

学習モードで現在のチャプターをクリアし、チャプター内の暗記フラグ率が **90%を超えた場合**、クリア状態として次のチャプターを解放する。

```text
現在のChapter
      ↓
学習モードでプレイ
      ↓
チャプター内の暗記フラグ率を確認
      ├─ 90%以下 → 未クリア / 次Chapter未解放
      └─ 90%超  → クリア → 次Chapter解放
```

- 判定対象は当該チャプター内の単語。
- 暗記フラグ率は `is_memorized == true` の単語数を基準に算出する。
- 90%ちょうどは「90%を超える」を満たさないためクリア条件には含めない。
- 一度解放されたチャプターは原則として再ロックしない。
- 解放状態・クリア状態はDBに保存し、アプリ再起動後も維持する。

##### 9. チャレンジモードではチャプターを解放しない

チャレンジモードでは全単語からランダム出題する既存仕様を維持する。ただし、チャレンジモードの結果からチャプター解放処理を実行してはならない。

##### 10. チャプター選択欄の初期表示

ゲーム選択画面を表示した際、チャプター選択欄の初期値は、その時点で**選択可能な最新チャプター**とする。

```text
Chapter 1のみ解放済み → Chapter 1
Chapter 1〜3解放済み → Chapter 3
Chapter 1〜7解放済み → Chapter 7
```

レベルを変更した場合も、変更後のレベルで選択可能な最新チャプターを初期表示する。

##### 11. 開始ボタン

開始ボタン押下時に以下を検証する。

1. ゲームモードが選択されていること。
2. レベルが選択されていること。
3. 学習モードの場合、選択チャプターが解放済みであること。
4. 選択条件に対応する出題対象単語が存在すること。

検証成功後、ゲーム画面へ遷移する。

- 学習モード: 選択チャプターを対象にゲーム開始。
- チャレンジモード: 既存仕様どおり全単語からランダム出題。

##### 12. 添付イメージの扱い

添付されたゲーム選択画面には3つのデザインパターンが提示されている。これらは現時点では**候補**であり、採用パターンは未決定とする。

| 候補 | 特徴 | 状態 |
| --- | --- | --- |
| パターン1 | シンプルなカード・ボタン中心 | 候補 |
| パターン2 | 方眼紙・切手風のレトロUI | 候補 |
| パターン3 | マップ・建物・コンパス等のゲーム世界観重視 | 候補 |

デザイン決定後も、ゲームモード、レベル、チャプター、最新解放チャプター初期表示、学習モード限定解放、開始ボタンという機能要件は維持する。

#### 🎵 ⑪ 相棒キャラクターのドットアニメーション仕様（Flame）

相棒キャラクターのアニメーションは、Flutterの通常UIではなくFlameを使用して実装する。

- **通常待機**
  - 小さな揺れや瞬き等のアイドルアニメーション。
- **歩行**
  - 左右移動に合わせた歩行アニメーション。
  - Flame側で移動速度・向き・アニメーションを制御する。
- **笑い**
  - 条件成立時に笑顔アニメーションへ切り替える。
- **睡眠**
  - 一定時間操作がない場合に睡眠状態へ遷移する。
  - 睡眠中は睡眠用アニメーションをループする。
- **特定条件成立時のエフェクト**
  - 条件を満たした場合、音符等のドットエフェクトを表示しながら笑う。
- **ゲームクリア帰還**
  - ホーム復帰時にハミング状態・専用演出を再生する。
- **お気に入りスタンプ**
  - Flame上で相棒キャラクターの胸部にスタンプバッジを重ねて表示する。

### 3.6 チャプター解放状態の保存

チャプター解放状態はアプリ再起動後も維持できるよう永続化する。実装方式は既存DB構成との整合性を確認した上で決定する。

最低限、以下を保持できること。

| 項目 | 説明 |
| --- | --- |
| `chapter` | チャプター番号 |
| `is_unlocked` | 選択可能か |
| `is_cleared` | 学習モードでクリア済みか |
| `memorized_rate` | 最新のチャプター内暗記フラグ率 |
| `cleared_at` | クリア日時 |

- 初期状態では各チャプター系列の最初のチャプターのみ `is_unlocked = true` とする。
- 学習モードで暗記フラグ率が90%を超えた場合、次チャプターを解放する。
- チャレンジモードではチャプター解放状態を更新しない。

| `lib/flame/characters/` | Flameキャラクター本体・スプライト |
| `lib/flame/animations/` | 歩行・笑い・睡眠・待機等のアニメーション |
| `lib/flame/movement/` | キャラクターの移動・向き・速度制御 |
| `lib/flame/effects/` | 音符・キラキラ等のドットエフェクト |
| `lib/flame/state/` | Flame側の状態・アニメーション状態管理 |

### 4.4 FlutterからFlameへのデータ連携

```text
Drift / Service
      │
      │ 定着率・相棒設定・お気に入りスタンプ等
      ▼
Flutter Screen
      │
      │ キャラクター状態を通知
      ▼
Flame Game
      │
      ├── Character
      ├── Animation
      ├── Movement
      ├── Effect
      └── State
```

Flame側でDBを直接操作することは基本とせず、Flutter / Service層で決定した状態をFlameへ渡す構成とする。

## 5. ドット絵・アニメーション開発方針

### 5.1 基本方針

- ドット絵キャラクターはFlameを中心に実装する。
- 通常のFlutter UI上にFlameの表示領域を組み込み、UIとアニメーションを分離する。
- キャラクターの「状態判定」はFlutter / Service側、「状態に応じた見た目・動き」はFlame側で担当する。
- キャラクターのアニメーションを画面ごとのFlutter Widgetだけで実装せず、Flame側に集約する。
- 将来的にキャラクター数が増えても、同じFlameコンポーネント構造を再利用できるようにする。

### 5.2 キャラクター状態の例

```text
idle
 ├── walk
 ├── laugh
 └── sleep

条件成立
 └── laugh + music_note_effect

ゲームクリア
 └── hum

定着率
 ├── silhouette
 ├── low
 ├── normal
 └── evolved
```

### 5.3 アニメーション素材の考え方

キャラクター画像を完全な1枚絵として画面ごとに作るのではなく、Flameで再利用できるドット絵スプライト／アニメーション単位で管理する。

必要なアニメーションは最低限以下を想定する。

- Idle
- Walk
- Laugh
- Sleep
- Hum
- 必要に応じて状態変化・進化演出

特定条件での音符・キラキラ等は、キャラクター画像そのものとは分離し、FlameのEffectとして実装する。

## 11. まとめ

```text
Flutter
├── 学習アプリとしてのUI・画面・DB・サービス
│

    └── ドット絵キャラクター・アニメーション・移動・エフェクト
```
